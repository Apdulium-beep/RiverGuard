# Выпуск версий RiverGuard

Автор приложения: **Apdulium-beep**.

## Структура

Каждая новая версия получает собственную локальную папку `versions/<версия>/`: `src`, `docs`, локальная `app`, README, сведения об авторе, лицензии и `version.json`. Нельзя заменять старый EXE новой программой под старым номером.

Текущая ветка GitHub содержит только текущую папку версии. После выпуска следующей версии предыдущая папка остаётся на компьютере, но исключается из текущей ветки; её проверенные исходники остаются в соответствующем теге. Большие EXE, временные файлы и локальные проекты не коммитятся. Готовая программа публикуется только вложением своего релиза.

Это уменьшает размер скачиваемых исходников и устраняет смешение версий; одинаковые данные в Git дополнительно переиспользуются. Само создание папок не уменьшает занятый диск. Существующий локальный `archive` сохранён без удаления и не загружается на GitHub.

## Порядок следующего обновления

1. Создать `versions/<новая версия>/`, перенести туда только нужные исходники и документацию, не копировать `bin`, `obj`, `SmokeTest` и старую `app`.
2. Обновить номер в `.csproj`, заголовке окна, README и `version.json`; указать `Apdulium-beep` как автора приложения. Сохранить обязательные уведомления компонентов.
3. Выполнить изменения и проверки. Не переписывать пользовательские проекты.
4. Запустить `tools/Publish-Version.ps1 -Version <новая версия>` с доступными `git`, `gh` и .NET SDK. Для нового номера скрипт проверит версию, соберёт программу, выполнит расчётные и интерфейсные тесты, создаст ZIP и SHA256, обновит указатель текущей версии, закоммитит выбранную папку, загрузит исходники и создаст соответствующий релиз.
5. Проверить опубликованные вложения. Исходники релиза должны открываться по тегу в той же папке версии. Уже существующий релиз скрипт не перезаписывает.

Публикация требует авторизованного доступа к репозиторию. Скрипт не хранит пароли или токены в файлах и не меняет видимость репозитория; перед публикацией он предупреждает, если репозиторий публичный. Выпуск производится при работе над обновлением; сам по себе документ не запускает фоновую публикацию.
