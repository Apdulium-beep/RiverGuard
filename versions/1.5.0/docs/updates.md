# Обновления RiverGuard 1.5.0

Автор приложения: **Apdulium-beep**.

## Поведение

Каждый обычный запуск вызывает одну фоновую проверку `https://api.github.com/repos/Apdulium-beep/RiverGuard/releases/latest`. Отсутствие соединения не мешает работе программы. Ручная проверка доступна на стартовом экране и в разделе сведений о модели; она повторно запрашивает GitHub, а не использует старый ответ.

Предлагаются только более новые стабильные версии с числовым номером из трёх или четырёх компонентов. Черновики, prerelease и понижения версии игнорируются. Если выполняется расчёт, открыто другое диалоговое окно или приложение не активно, предложение откладывается до доступного состояния; оно не прерывает текущую операцию. После «Позже» автоматическое предложение не повторяется в этом сеансе, но остаётся кнопка ручной проверки.

«Обновить и перезапустить» загружает комплект Windows x64 и SHA256. Можно отменить загрузку. Перед перезапуском обычный обработчик закрытия предлагает сохранить изменённый проект. Если пользователь отменил закрытие, программа остаётся открытой, а загруженное обновление можно применить позже той же кнопкой. Сохранённый открытый проект передаётся новой версии стандартным аргументом командной строки.

## Защита загрузки

- Исходный адрес релиза и названия файлов привязаны к одному репозиторию и номеру версии.
- Разрешён только HTTPS. Перенаправления допускаются только на GitHub и его домены выдачи вложений, максимум пять переходов.
- Сопоставляются заявленный и фактический размеры, SHA256 из отдельного файла и digest вложения GitHub, если он опубликован.
- Архив ограничен 512 МБ; распакованные данные — 1 ГБ и 256 записей. Проверяется весь список файлов до распаковки.
- Разрешена одна папка `RiverGuard-<версия>` с плоским комплектом приложения. Запрещены обходы путей, абсолютные пути, дубликаты без учёта регистра, символьные ссылки, зарезервированные имена, скрипты и файлы проектов.
- Должны присутствовать `RiverGuard.exe` и уведомления компонентов. Проверяются сигнатура Windows EXE и номер версии из его ресурсов.

Проверка SHA256 не заменяет цифровую подпись издателя. Механизм доверяет HTTPS-публикациям указанного GitHub-репозитория; независимая Authenticode-подпись не добавлялась. При ошибке новая программа не запускается, а старая не перезаписывается.

## Файлы и доступ

Установка выполняется без администратора в `%LOCALAPPDATA%\RiverGuard\Versions\<версия>`. Если папка уже существует, используется новое уникальное имя, а не перезапись её содержимого. Загруженный временный архив удаляется после завершения или ошибки. Старые установленные версии автоматически не удаляются.

Проекты в документах, импортированные файлы и индекс библиотеки не переносятся установщиком. Действуют только обычное сохранение и восстановление сессии при закрытии приложения. Обновляется ярлык приложения на рабочем столе и найденные ярлыки, которые действительно указывали на запущенную сборку; чужие ярлыки не переназначаются.

Программа не запрашивает пароль GitHub и не содержит токена. Автоматическая проверка возможна при доступном публичном релизе; приватный репозиторий без авторизации, сетевые ошибки и ограничения API обрабатываются как недоступность проверки, не как сообщение «обновлений нет».

Версии до 1.5.0 не содержат этого механизма. Переход на 1.5.0 требует однократного запуска новой сборки; следующие обновления предлагаются самой программой.
